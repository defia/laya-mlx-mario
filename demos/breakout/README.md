# Laya Breakout · 本地终端打砖块

球拍的每一步都由 Laya（`aac6fef/laya-multilingual-mlx`，FP16，本地 MLX 推理）做出真实决策，
一次 `Agent.predict` 批量回答三个类型化问题：

| 面板显示 | 实际含义 |
|---|---|
| 左移 / 不动 / 右移 | Laya `choice` 对三个动作的概率分布 |
| 漏接风险 | Laya `noul`：P(球拍不动这球会落地) |
| 紧迫度 | Laya `score`：从容 / 正常 / 紧迫 / 火烧眉毛 的期望档位 |

## 运行

```bash
# 交互模式（终端至少约 90 列 × 36 行）
uv run --extra demo python -m demos.breakout

# 常用参数
uv run --extra demo python -m demos.breakout --fps 20        # 决策节奏
uv run --extra demo python -m demos.breakout --seed 42       # 固定种子
uv run --extra demo python -m demos.breakout --strategy steer # 起手就控球
uv run --extra demo python -m demos.breakout --unassisted    # 关闭安全护盾（裸模型）
uv run --extra demo python -m demos.breakout --headless --steps 600   # 无界面跑测
```

按键：`1/2` 切换接球策略（稳接 / 控球）· `Q` 退出 · `P` 暂停。

## 玩法：连击计分

一次弹球期（两次触拍之间）连续击碎的第 k 块砖得 k 分——一杆 3 连击 = 1+2+3 = 6 分，
25 连击 = 325 分。砖墙顶部两行实心，下面四行沿"右上对角线"每 5 格开一条通道：
只有向右上飞的球能顺着通道钻进墙里连环反弹，所以**接球时用拍面哪一侧接**，
直接决定下一波能连几块。

两种策略只作用于几何层（提示词永远是纯事实，数字随策略变化）：

- **稳接**：拍心正对来球落点。拍面中央命中会把球镜像弹回去（水平方向翻转），
  球路左右交替，稳妥但连击听天由命。
- **控球**：几何层把球拍分别停在三个接球点（中央 / 左拍角 / 右拍角）用真实
  tick 各模拟一整波弹球，选**连击得分最高**的接球点（平局偏向中央——前期
  镜像钻出的通道正是后期深连击的本钱）。拍角（±3 列）而不是拍沿（±2 列）是
  有意的：模型定位有 ±1 列抖动，拍角目标能保证抖完仍落在强制转向区。
  右侧面板的"连击评估"行实时显示 `左沿+N 中央+N 右沿+N` 和本步选中的方向；
  前期砖墙没洞时三方向收益相同，控球自然与稳接一致（提示词也一字不差），
  墙一旦开洞，接球点数字就会开始偏移。

## 模型决策 vs 护盾

与官方 Snake demo 相同的 **feature-assisted** 语义：

- **特征层（非模型）**：预测球的落点列与到达步数，直接写进原文
  （"接球点在球拍中心左侧 11 列，3 步后到达，应向左移动"）——模型不用自己做列号减法。
- **模型真实决策**：在"可行动作集"内选择。可行动作集 = 执行该动作后，
  追球安全网策略仍能把球接住的动作；末段（≤8 步）额外收紧：偏离接球点的动作不再可行。
- **护盾（SHIELD）**：模型选了不可行动作时，改执行可行动作并计数标记。

对照实测（FP16，~9ms/决策，连击计分规则下）：

| 配置 | 得分(1500步) | 砖数 | 最高连击 | 漏接 |
|---|---|---|---|---|
| 模型 + 护盾 · 稳接（seed 3 / 11） | 694 / 372 | 86 / 60 | 25 | 0 |
| **模型 + 护盾 · 控球**（seed 3 / 11） | 695 / **411** | 87 / **92** | 25 | 0 |
| 纯几何贪心 · 稳接（3000步对照） | 442 | 54 | 28 | 0 |
| **纯几何贪心 · 控球**（3000步对照） | **570** | **93** | 28 | 0 |

模型把优化器的接球点执行出来时优势兑现（seed 11：+39 分 / +32 砖），
执行抖动大时就退化为稳接水平（seed 3：基本打平）——这正是"模型=驾驶员、
几何=副驾"语义的直观展示。护盾干预 43-189 次/1500 步（末段方向纠错），
漏接恒为 0；纯随机乱打 + 护盾 3000 步同样 0 漏接。

护盾 0 漏接在多种子下复现；纯随机乱打 + 护盾 3000 步同样 0 漏接
（护盾纠正 ~400 次）——安全网本身是严密的。模型局能打出对照组 3 倍以上的分数，
因为连击寻优的接球点真的被模型执行了出来。

## 提示词调优记录（A/B 实测）

这个 checkpoint 在打砖块域有个"向右"先验，提示词每多一句都可能被带偏：

1. **方向必须算好写进原文**：只给两个列号（落点列、拍心列）时模型选对方向仅 18%，
   写成"接球点在球拍中心左侧 19 列…应向左移动"后升至 65-67%。
2. **策略提示句整体移除**：实测任何建议性语句（"稳稳接住"→选不动、"用拍面中央"→选错
   方向）都降低准确率，终版原文只保留事实。
3. **标签措辞**：不可行动作标 "不安全，会错过来球。" 时末段服从率不足（0.48 选反向），
   改成 "危险，球会落地漏接。" 后左右两向都服从（0.60/0.70）。
4. **非最佳选项不带方向词**：如 "向右偏离接球点" 里的"右"会喂给模型反向信号。
5. **三个真 bug**：可行性 roll-out 比现实多出一次幽灵移动（多 2 列余量），导致护盾
   "救不活也判可行"，修正后随机乱打 3000 步漏接 55→0；拍面中央命中保留水平方向导致
   球路单调循环（用户试玩发现），改为镜像反弹后连击机制才真正成立；反弹瞬间的
   水平位移一度沿用旧方向（用户发现"先弹出去再变向"），改为出射方向当拍生效，
   同时连击寻优的模拟也必须用真实 tick 跑完整弹球期，否则收益评估会系统性错位。
