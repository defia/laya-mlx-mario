# Laya Mario · 本地模型玩超级马里奥

移植自 [fhshaik/typesafe-mario](https://github.com/fhshaik/typesafe-mario)：NES 模拟器
（gym-super-mario-bros + nes-py）的状态解析器、七个手柄宏动作、实时仪表盘和逐决策
日志全部保留；唯一的替换是把远程 TypeSafe/Jev API 换成本地
`laya-multilingual-mlx`（FP16，~15ms/决策，零网络）。两边 API 本来就是同构的
`choice / noul / score` 三种类型化判定，一次 `Agent.predict` 全部回答。

```text
NES 模拟器 → RAM/遥测解析器 → 事实性中文提示词 → Laya predict → 手柄输入
```

## 运行

项目已 pin 到 Python 3.13（gym-super-mario-bros 9.x 要求）。

```bash
uv sync --extra mario --extra demo   # 首次安装

# 推荐：游戏画面 + 模型遥测仪表盘（pygame 窗口）
# 默认 = pure 模式 + 中文权重 + step 菜单 + 9帧/拍 —— 通关 1-1（240 拍触旗，
# 全程仅 108 帧卡墙）
uv run python -m demos.mario.cli play

# 英文 421M 对照（x=2466；其选择对文本免疫，措辞搜索对它无效）
uv run python -m demos.mario.cli play --model models/hub/laya-mlx --frames-per-decision 10

# 各关最佳配置（仪表盘 1-4 切换保留启动配置——默认 step+9帧 是 1-1 专用的，
# 在 1-3/1-4 上只有 384/228；要复现下表成绩需带参数启动）
uv run python -m demos.mario.cli play --env SuperMarioBros-1-2-v0 --actions hop   --frames-per-decision 6   # 978（柱前活锁，Esc 退出）
uv run python -m demos.mario.cli play --env SuperMarioBros-1-3-v0 --actions spring --frames-per-decision 10  # 743
uv run python -m demos.mario.cli play --env SuperMarioBros-1-4-v0 --actions spring --frames-per-decision 10  # 546

# 混合步态（最像人玩）：平地跑、遇敌/沟/墙触发跳，x=829（卡在第一个台阶塔）
uv run python -m demos.mario.cli play --actions mix --run-hint

# 对照：护盾+机动+判定标签的旧配方（x=1518 基线）
uv run python -m demos.mario.cli play --mode assist

# 只看游戏窗口 / 无界面跑测
uv run python -m demos.mario.cli play --display game
uv run python -m demos.mario.cli play --display none --max-decisions 120

# 不开模拟器、不加载模型，只看结构化状态和提示词长什么样
uv run python -m demos.mario.cli state-demo

# 单状态 A/B 探针：把历史日志里的关键状态喂给不同提示词变体
uv run python -m demos.mario.probe demos/mario/artifacts/run-*.jsonl --where enemy-close
```

仪表盘：`R` 或 Restart 重开一局 · **`1`-`4` 随时切换 World 1-1~1-4** ·
`Esc`/`Q` 退出。窗口里的轨迹与 headless 日志**逐步一致**（同步决策循环）。
每步决策写入 `demos/mario/artifacts/run-*.jsonl`（含提示词原文、概率分布、
noul/score、时延、奖励）。常用参数：`--mode pure|assist`、
`--actions step|spring|hop|mix|core|full`（手柄宏菜单）、
`--frames-per-decision 9`（决策节拍）、`--no-grid`（去掉 ASCII 地图）、
`--seed`、`--model models/hub/laya-mlx`（英文 421M）、`--policy heuristic`
（离线对照）。轨迹完全确定：同配置两次运行逐步一致（模型确定性输出 +
1-1 无随机敌人刷新，种子不改变轨迹）。

**地图的悖论**：作为信息它是死重（去掉后 spring f12 轨迹逐拍不变、时延还降
4ms；地形读数零梯度、情境触发走敌情句模板）；但作为 token 序列它现在承重——
纪录配置 3155 是带着地图调出来的相位，`--no-grid` 会重掷到 1420。"无用"的
字也在定义轨迹，这是刀刃敏感性的极端体现。

## 决策语义

两种模式（`--mode`）：

- **pure（默认，研究主线）**：提示词 = 状态事实 + 常驻游戏规则块（死亡规则、
  踩扁规则、跳跃物理："滞空约44帧，全速一跳约7格"）。没有护盾、没有脱困机动、
  选项标签不带任何判定——起跳时机、敌情应对全部由模型自己判断。
- **assist（1518 基线）**：在 pure 之上叠加几何护盾（只否决"可证明必死"）、
  卡墙脱困机动、地形判定标签。

共同部分（与 snake/flappy/breakout 相同的 feature-assisted 配方）：

- **解析器（非模型）**：从 NES RAM 提取马里奥运动、局部碰撞网格、最多 3 个敌人
  的位置/相对速度，并完成全部时间算术——接触倒计时、起跳窗口、跨沟状态，全部以
  事实句写进原文（"最近的板栗仔在前方26像素，每帧接近2像素，预计13帧后接触"）。
- **模型真实决策**：`choice` 选下一个手柄宏；同一个 predict 同时回答 noul（现在
  是否该起跳）和 score（危险度 0-2，仪表盘实时显示）。
- **敌人信息只报事实**：位置（前方/身后 N 像素）、相对马里奥的速度（每帧接近/
  远离 N 像素）、接触倒计时；马里奥自身速度（像素/帧）也写进原文。
- **手柄宏菜单（`--actions`）是基础设施的一部分**：step（默认）= right_jump/
  left 两键（常速短弧）；hop = 加 right_run/right_run_jump 四键；core = 加回
  普通 right；full = 上游 7 键。菜单怎么定见下方研究记录第 8 条。

## 移植时修的问题（上游也有）

1. **速度单位 bug**：敌人的相对速度取的是"两次解析之间"的位移差，headless 模式
   一次解析跨 8 帧，代码却按每帧速度使用——导致接触倒计时永远只剩几"帧"、起跳
   窗口从敌人一进视野就是负数（"已错过"），`jump_must_start_this_decision` 从未
   触发过。修复：解析器接受 `frames_elapsed` 并归一化速度与滞空帧数（玩家自身
   dx/dy 同步归一化）。
2. **headless 缺松键边沿**：连续两次决策都选跳跃动作时 A 键一直被按住，SMB 不会
   二段跳——马里奥只跳一次后贴在管壁上原地不动。dashboard 循环本来就有这个修正，
   headless 没有；补齐后 x 卡死在 434（第一根绿管前）的问题消失。
3. **瓦片页映射 bug**：局部网格按世界坐标取瓦片页号，采样越过后一页 256px 边界
   就读到错误页——产生"8 格宽幽灵沟"、x>550 后地面消失。修复：用 SMB 页寄存器
   （RAM 0x6D/0x86）按视口换算；支撑判定改为任意深度（台阶下降不再误判为沟）；
   沟宽因下一页流式填充不实做 4 格封顶。
4. **标签服从率**：危险标签用抽象措辞（"本决策不起跳就错过窗口"）时，模型被
   提示词里的惯性句（"上个动作right执行160帧"）锚定，20 步全选 right 一头撞死在
   板栗仔上；改成点名后果的具体措辞后 right 概率 0.36→0.12、跳跃家族 0.77。

能全活，距离 = 步态 × 关卡几何的确定性乘积。

## 提示词研究记录（这轮 POC 的主要产出）

结论先行：**该模型 = 单步先验 + 强词汇锚定 + 不读数字**。提示词能压制"明显向前
送死"、能放大模型本来就想要的跳跃；不能安装新机动、不能逆转跳跃先验、不能表达
多步计划；情境数字（敌距/倒计时/沟宽）对选择分布零梯度。pure 模式的突破全部来自
**动作空间设计**，不是提示词措辞。

1. **动作词锚定（最强变量）**：上下文里出现跳跃动作名（惯性句"上个动作right_jump"）
   会把跳跃家族概率从 ~0.36 拉到 0.99，此后任何标签都压不住；句子里只要有"起跳"
   二字（哪怕在中性规则句里）同样引爆（0.42→0.80）。惯性句已去动作名（保留时长与
   结果）。网格无关（有无网格都是 0.99）。
2. **刀刃敏感性**：开阔地上各动作概率本就 0.2-0.3 均匀，任何 token 变化都可能翻转
   argmax——"命2条"三字就让某步 right↔jump 翻转并混沌级联整局轨迹。也解释了
   为什么每个"合理"的措辞改动都曾在某局回归。（后经确认本环境完全确定性：
   同配置轨迹逐步一致，种子无效，见第 10 条。）
3. **标签不对称律**：顺着先验的标签有效（撞上后果压制 right：0.36→0.12；正向跳跃
   标签放大跳跃：0.48→0.66）；逆着先验的标签无效（任何"现在起跳会落进沟里/越不过"
   的写法都压不住跳跃家族 0.6-0.9）。
4. **不可表达的机动**：高墙前 P(left) 恒 0.02（"后退才能助跑"写进标签也没用）；
   全速跑标签对 P(right_run) 无效（0.12-0.18）。多步计划与移动模式超出文本层，
   assist 模式由"卡墙脱困机动"（后退4拍→全速3拍→助跑跳→保持弧线2拍）代管。
5. **"模型自己判断起跳"在文本层不可实现**：(a) 两段式自反馈——把模型 noul 判定
   喂回 choice 确实让跳跃家族 0.44→0.75，但 noul 在本域恒为"是"（开阔地 0.98、
   管子前 1.00），没有时机分辨力，效果只是"跳跃"一词的锚定；连"前置判定：现在
   不需要跳跃"都把跳跃家族拉到 0.68（词汇锚不解析否定）。(b) 无跳跃词的算术紧迫
   事实不驱动它（0.36-0.44 恒选 right）。
6. **情境数字零梯度（本轮新增，最关键）**：把敌距从 32px 压到 4px、倒计时从 16 帧
   压到 2 帧，right 概率纹丝不动（0.27-0.28，合成状态逐一验证）——模型不读这些
   数字，"告诉它来不及了"在信息层面就不成立。同理"马里奥站在高台、比地面高 4 格"
   的事实也不改变选择（right_run_jump 0.44→0.49，反而更强）。目标句锚定
   （"选择能让马里奥活着向右前进的动作"）把"向右"锚到 right_run 上，跳跃家族
   0.45→0.33——方向反了。
7. **护盾与机动计数**：每步决策的 [SHIELD]/[RESCUE] 写入 jsonl，仪表盘面板
   显示累计次数，headless 每步打印标记。
8. **动作菜单拆分效应（pure 模式的突破口）**：菜单里有 2 个前进速度
   （right/right_run）+ 3 个跳跃时，"前进"意图集中在 right 上恒为多数派
   （贴脸 0.27），跳跃意图被三个选项摊薄（各 0.24）永远赢不了 argmax——即使跳跃
   家族总质量 0.51 > right 0.22。删掉普通 right（hop 菜单）后前进只剩跳跃，贴脸
   状态 right_run_jump 0.41-0.43 成为第一，模型表现成"全程兔跳"步态——这个
   涌现步态结构性清过全部板栗仔与绿管（x 286→1123）。再删 right_run_jump
   （step 菜单）得到常速短弧步态，塔顶弹射距离减半。
9. **常驻规则块有益**：死亡/踩扁/跳跃物理规则（"滞空约44帧，全速一跳约7格"）让
   跳跃先验整体温和上移，hop 菜单下 1412 vs 无规则块 1128；情境化的规则句
   （只在敌情句里塞"落到它头顶可以踩扁它"）无效（0.45→0.44）。
10. **确定性与节拍相位**：模型确定性输出 + 1-1 无随机敌人刷新 ⇒ 同配置两次运行
    逐步一致（已验证 91 拍全同），种子不改变任何东西，单局 A/B 是精确实验。
    决策节拍 frames_per_decision 是全局相位旋钮：hop 菜单只有 6 帧/拍能让第一
    个台阶塔的弹射相位落进安全带（5/7/8/10/12 全部 x≈1123-1128 落沟）。
11. **pure 模式的剩余死因**：台阶塔顶（比地面高 4 格）满速起跳的飞行弧线
    ~140-200px，落点是沟群（1412 与 assist 的 1518 死在同一沟段）。从塔顶往下
    看的网格因 NES 流式填充读不出下坡台阶（读到 7 格宽幽灵沟），高度事实又
    零梯度——这是当前 checkpoint 在纯事实输入下的结构性上限。
12. **选项顺序位置偏差（通用发现）**：同一状态、同一提示词，仅 choice 选项在
    问题里的排列顺序不同，概率可摆动 ~0.2（实测 x=285 贴敌状态：rj 排前
    rj=0.55/rr=0.39，rr 排前 rr=0.60/rj=0.34）。单进程内推理逐位确定、跨进程
    复现一致，因此差异只能来自选项 token 顺序。做 A/B 时菜单顺序必须固定，
    它同时也是一个可用的先验旋钮。
13. **"没必要不要跳"指令实验（行为 vs 距离的权衡）**：常驻指令"平整的地面上
    向前奔跑是更快的移动方式"+ 菜单 {right_jump, right_run, left}（跳跃排前）
    在英文权重上造出了唯一的混合步态——开阔地跑（rr 0.53）、敌人出现翻转为跳
    （敌距 40px/接触 17 帧时 rj 0.55 vs rr 0.39，带余量）。英文翻译版指令
    （"Running is the fastest way..."）反向锚定（rr 0.91），中文指令对英文
    权重反而有效。最初混合步态卡在第一根管子（434，贴管 right_run 到超时，
    点名"高墙和管子需要跳跃才能越过"也不翻）。
14. **触发器的通道与模板转移（本轮核心进展，混合步态 434 → 829）**：控制变量
    定位——敌人翻转由**敌情句**承载（删句翻转消失 rr 0.66；删网格 E 翻转保留
    rj 0.48），触发的是句式模板而非敌距数字。把地形事实改写成同款模板（"最近的
    沟在前方24像素，相对马里奥每帧接近3像素，预计8帧后到达沟沿"——纯事实
    重述）后：沟在 1-2 格翻转（余量 0.06-0.10）、管子在 1 格刀刃翻转；再给
    高墙（≥3格）追加一句短重复（"前方有高4格的障碍"）可把窗口推到 2-3 格
    （rj 0.42→0.54，够助跑起跳）。对 2 格管子双写会连锁重掷回 434，所以只对
    高墙双写。最终混合步态 x=829（216 跑+32 跳，过管子、板栗仔群、两道沟），
    死在第一个台阶塔立面：到达时刚跳完板栗仔、速度只有 2，1-2 格起跳弧顶
    ~3.5 格 < 塔高 4，差半格撞脸。**金字塔需要持续满速，只有全程跳跃步态能
    维持——行为多样性与距离是此 checkpoint 上的根本交易。**
15. **指令与模板均已固化为配置**：`--actions mix --run-hint`（跳跃选项必须
    排在菜单最前，顺序摆动 ~0.2）；pure 模式的地形句默认改用敌情模板
    （assist 不变，保持 1518 基线可比性）。默认配置（step f10 EN）在模板
    改动前后均为 2466，无回归。
16. **双写技巧的适用边界**：短重复句放大高墙触发（rj 0.42→0.54）但对敌情句
    反而削弱（0.55→0.49）——双写不是通用放大器，每个句式要单独测。触发器
    只认 right_jump：菜单换成 {right_run_jump, right_run, left} 时敌情模板
    翻转消失（rr 0.61 vs rrj 0.32），rr-vs-rrj 的先验鸿沟不可弥合，混合步态
    无法用按住 B 的跳跃保持速度。
17. **几何封顶的混合步态**：第一个台阶塔前的最后一对板栗仔离塔面仅 20-40px，
    任何为板栗仔起跳的弧线都直接撞进塔立面——不是触发时机问题，是关卡几何
    对"跳完减速再爬墙"步态的结构性封锁。
18. **2466 之墙的护盾诊断（两次修复尝试，均回滚）**：致命起飞点（x=2402，
    高砖段上）的网格其实**看见了**那个 2 格宽的洞（gap=3w2）——护盾有数据，
    但两个因素让否决漏过：(a) "障碍遮蔽"守卫（1 格方块 ≤ 沟距就放弃否决，
    本意防管后幽灵沟）把真沟一并挡掉；(b) 射程公式用当前 dx（2px/帧→预测
    5.5 格），实际弧线因砖顶压顶只飞了 4 格——高估 1.5 格恰好吃掉否决裕度。
    修复尝试 1（1 格障碍不遮蔽 + 步行跳射程 1.7px/帧）：金字塔顶的 7 格幽灵
    沟被放行否决，爬台阶合法跳全灭，assist 跌到 1128；修复尝试 2（加"读数
    ≥5 格=幽灵"过滤）：救回 1405 但其他否决点连环重掷，zh 从 1946 跌到 671。
    结论：护盾的否决裕度是亚格级且与轨迹混沌耦合，全局公式改动无法只修一处；
    已回滚到 1518 时代公式（assist EN step f10 复测 2466）。真正的修法需要
    按站点（ceiling 压顶、遮挡高度）分类的射程模型——留待后续。
19. **措辞-相位搜索（zh 专属杠杆，1763 → 3155）**：zh 的刀刃敏感意味着背景
    块的每个诚实改写（像素 vs 格、语序、紧简、目标句式）都是一次合法的整局
    相位重掷。6 轮 60+ 张"彩票"后：物理句用像素单位（110/80/45 像素）+ step
    菜单 + 9帧/拍到达 x=3155——措辞只在 zh 上有此效应（EN 分布尖峰、对文本
    免疫），且 spring 步态对措辞免疫（rrj 偏好太深，10 个变体全 1763）。
    提及"B键"会反向锚定（玩家按 B 跑 → 模型选跑 → 279 撞敌）。到达终点
    阶梯的 6 个相位全部死在第 2 级立面：8 级台阶需要 8 连 16px 精度落点，
    常速跳链的相位空间里这是最后一道墙。**记录的本质：措辞参数化的相位
    选择——"110像素 vs 111像素"即换轨迹，距离记录是措辞搜索找出的、完全
    确定性的一条活相位。**
20. **卡墙彩票与双目标措辞选择（3155/711帧 → 3150/108帧）**：纪录轨迹在两面
    4 格高墙上各卡很久（x≈894 卡 279 帧、x≈2217 卡 324 帧，合计占全程 22%）。
    死因不是无知——状态文本如实写着"前方1格有4格高的障碍"——而是 step 菜单
    没有助跑选项，原地满跳恰好 4 格高，能不能站上墙顶是像素/帧级抽签：模型
    反复 right_jump 撞墙弹回（left 只被刀刃选中做半步后退），直到某跳的弧顶
    恰好落在墙沿。两条轨迹逐拍对比证实分岔只是 #65 一步的刀刃（left vs
    right_jump）。彩票时长是几何分布：同族配置里 v5-f10 在 x=2222 抽了 2250 帧、
    v1-f10 抽了 5589 帧（93 秒）才中奖。优化方法 = 给措辞搜索加第二维目标
    （卡墙帧 = x 连续 ≥5 拍不动的时间），复评全部历史变体日志后选出
    **c7s（3150，108 帧）**为默认：两面墙首跳即过，240 拍触旗通关（快 22%）。
21. **"终点阶梯之墙"不存在——记录层误读的修正（2026-09-21）**：c7s 默认
    轨迹在 x=3150 戛然而止，末拍 `dead=False、剩 2 命、剩 291 时间`，状态
    文本还写着"终点旗杆在前方 114 像素"。复查终止帧的 `info`：**`flag_get=True`
    ——触旗过关**。模拟器在碰旗瞬间返回 terminated，决策循环随即 break，
    最后一次解析永远看不到过关 RAM 状态，jsonl 末拍的 `stage_clear=False`
    造成"全部死在 3148-3155"的集体误读：**6 个"死在阶梯"的相位全部通关**
    （末拍 dead=False/lives=2 复核），终点阶梯 8 级台阶被 step 跳链逐级正常
    攀爬，"8 连 16px 精度落点"的墙从未存在——真正的墙只有第 20 条里的
    两面 4 格高墙。修复：`_record_decision` 现在把终止帧的 `flag_get` 写进
    jsonl 并改写该拍 `stage_clear`，headless 打印 `[STAGE CLEAR]`，仪表盘
    顶端显示 "Stage clear!"。**经验：判断"死亡"必须看终止原因，x 停在
    3148-3155 恰是旗杆位置本身。**
22. **1-2 战役与"不会后退"的封顶（~40 张彩票的完整解剖，2026-09-21）**：
    x=978 的"7 格高墙"实为**顶天立地 2 格宽的立柱**，柱后紧贴 3 格高的金币
    平台。脚本化嫁接实验（确定性轨迹前缀到柱前 + 后退 60-120 帧 + 全速助跑
    + 定点起跳）证明立柱**根本不封死**：起跳点 889-984 共 12 组里 11 组越过
    并一路跑到 1180+。真正的三重杀区在 850-990：(a) 库巴在 900-950 巡逻，
    落地走地面即被撞（887 死法）；(b) 900-930 段低天花板恰在满跳弧顶——
    撞顶水平速度清零，坠落砸在库巴身上（924 死法）；(c) 贴柱弹跳循环——
    模型永远不会选 left 后退助跑（P(left)≈0.05），只能从静止原地纵跳，
    x 恒 978，几何上永远过不去（hop f6 系 1200 拍活弹到预算耗尽）。常速弧
    步态（step）另有数学封顶：高过平台高度的水平窗口 ~25px < 立柱宽 32px。
    **~40 张票**（hop/spring/mix × 4-16帧/拍 × 7 措辞 × 菜单顺序）零命中。
    两条新规律：**首位置律**——菜单第一个选项吃概率加成，right_jump 必须
    排第一，换 right_run/right_run_jump 排第一则所有配置死于 x≈186 第一只
    板栗仔（遇敌跑不遇敌跳）；**措辞敏感性与跳跃深度绑定**——spring
    （rrj 偏好深）在 1-2 对措辞全免疫（f13/f14 三措辞逐位相同），hop
    （混合步态）敏感（f7 四措辞 = 924/652/661/924）。1-2 的最终答案：
    **关卡本身可通关（立柱窗口存在），封顶的是"主动后退助跑"这一多步
    行为，与 1-1 混合步态的金字塔封顶（第 14/17 条）同构。**
